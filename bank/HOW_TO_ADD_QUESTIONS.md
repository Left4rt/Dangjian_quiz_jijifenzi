# 题库制作与新增指南（HOW_TO_ADD_QUESTIONS）

> 本文件可直接交给 AI：把一段题目原文连同本文件发给 AI，让它「按本指南把题目转换成题库 JSON」即可。
> 也可供人工对照填写。

---

## 一、整体机制（先理解再动手）

本程序的「题库」与「主程序」是分离的：

- 主程序（`index.html` + `js/` + `css/`）只是一个**加载器**，本身不含任何题目。
- 所有题目放在 `bank/` 文件夹里的若干 **题库 JSON 文件**（如 `set1.json`）。
- `bank/manifest.json` 是**清单**，告诉程序「有哪些题库文件、是否启用」。

因此，**新增题目只需两步**：

1. 把新题写成一个题库 JSON 文件，放进 `bank/`；
2. 在 `bank/manifest.json` 的 `banks` 数组里加一条记录指向它。

部署到 GitHub Pages 后，刷新页面，程序会自动拉取 manifest 与各题库文件并合并显示。**不需要改动任何 js 代码。**

---

## 二、题库文件格式

一个题库文件形如（`questions` 下按题型分组）：

```json
{
  "id": "set4",
  "title": "二十届四中全会专项题",
  "questions": {
    "single": [ ...单选题... ],
    "multi":  [ ...多选题... ],
    "tf":     [ ...判断题... ],
    "fill":   [ ...填空题... ]
  }
}
```

- `id`：题库唯一标识，**建议与文件名、manifest 中的 id 保持一致**（如文件 `set4.json` → id `set4`）。仅用于内部 ID 前缀，不直接展示给用户。
- `title`：题库显示名称。
- `questions`：四个题型数组，可缺省其中某些（没有就不写或写空数组 `[]`）。

> 程序也兼容「文件本身就是 `{ "single": [...], "multi": [...], ... }`」这种没有外层 `questions` 包裹的写法，但**推荐用带 `questions` 的标准结构**。

## 三、四种题型的字段规则

### 1. 单选题 `single`
```json
{
  "type": "single",
  "question": "（  ）是中国特色社会主义最本质的特征。",
  "options": { "A": "人民民主专政", "B": "中国共产党领导", "C": "政治协商制度", "D": "人民代表大会制度" },
  "answer": "B",
  "explanation": "中国共产党领导是中国特色社会主义最本质的特征。"
}
```
- `options`：对象，键用大写字母 `A B C D`（可到 `E F`）。
- `answer`：**单个大写字母**，对应正确选项。

### 2. 多选题 `multi`
```json
{
  "type": "multi",
  "question": "中国式现代化的特征包括（  ）。",
  "options": { "A": "人口规模巨大", "B": "全体人民共同富裕", "C": "物质精神协调", "D": "人与自然和谐共生", "E": "走和平发展道路" },
  "answer": "ABCDE",
  "explanation": "五大特征全选。"
}
```
- `answer`：**多个字母连写、按字母顺序**，如 `"ABCD"`、`"BCE"`。
- 判分要求「完全一致」：用户少选、多选、错选都算错。

### 3. 判断题 `tf`
```json
{
  "type": "tf",
  "question": "党内禁止任何形式的个人崇拜。",
  "answer": "正确",
  "explanation": "党章明确规定。"
}
```
- **无 `options`**。
- `answer`：**只能是中文「正确」或「错误」**两个词之一（不要写 `true`/`A`/`对`）。

### 4. 填空题 `fill`
```json
{
  "type": "fill",
  "question": "（  ）是党的根本宗旨。",
  "answer": "全心全意为人民服务",
  "aliases": ["为人民服务"],
  "explanation": "写入党章总纲。"
}
```
- **无 `options`**。
- `answer`：标准答案文本。
- `aliases`（可选）：等价答案数组。用户输入任一别名也判对。
- 判分时会自动忽略空白、把全角括号 `（）` 视同半角 `()`，并对标点做宽松处理，但**核心文字必须正确**。

### 关于 `explanation`（解析，强烈建议每题都写）
本题库的每道题都配有解析。好的解析不仅给出结论，更要：
- **讲清相关知识点**：说明该结论出自哪条规定 / 哪次会议 / 哪个论述。
- **做相似知识点辨析**：把容易混淆的干扰项点出来，例如「第一动力（创新）/ 第一资源（人才）/ 第一要务（发展）」「合宪性审查 / 合法性审查」「留党察看最长两年（不是一年）」等。
- 判断题解析要点明「正确 / 错误」的依据，错误项要指出错在哪个字眼。

示例：
```json
{ "type": "single", "question": "（  ）是引领发展的第一动力。",
  "options": {"A":"科技","B":"人才","C":"创新","D":"发展"}, "answer": "C",
  "explanation": "创新是引领发展的第一动力。辨析：人才是第一资源，科技是第一生产力，发展是第一要务，‘第一动力’特指创新。" }
```

## 四、ID 规则（很重要，决定去重与跨设备同步）

- **不要手写 `id` 字段。** 留空即可。
- 程序加载时会自动按 `题库id__题型__四位序号` 生成稳定 ID，例如 `set4__single__0007`。
- 这样能保证：
  - 同一题库内题目 ID 稳定，便于错题本/收藏夹长期引用；
  - 不同题库之间 ID 不冲突。
- 如确有特殊需要手写 `id`，必须保证**全局唯一**且**不与已有题库冲突**，否则错题/收藏的关联会错乱。一般情况下**强烈建议不写**。

---

## 五、去重规则（你可以放心地放入重复题）

程序在加载后会**自动去重**：

- 判重依据 = `题型 + 题干归一化文本`（归一化会去掉空白、标点、全/半角差异等）。
- 题干「实质相同」的题，只保留**第一个出现**的（按 manifest 中题库顺序、题库内题目顺序）。
- 被去掉的重复题，其旧 ID 会通过「别名映射」指向保留下来的那一题，因此**旧的错题/收藏记录不会失效**。

所以：

- 你可以新建题库时不必担心和老题库重复；
- 但**同一句话答案不同**的两道题会被视为重复而只留其一——若你确实想保留某变体，可在题干里加一点区分性文字。

## 六、新增一个题库的完整操作清单

1. 新建文件 `bank/setN.json`（N 取下一个序号，或任意有意义的英文名，如 `bank/exam2025.json`）。
2. 按第二、三节写入题目，`id` 字段留空。
3. 打开 `bank/manifest.json`，在 `banks` 数组追加一条：
   ```json
   { "id": "setN", "file": "setN.json", "title": "题库显示名", "enabled": true }
   ```
   - `id` 与文件主名一致；`file` 是相对 `bank/` 的文件名；`enabled` 设 `false` 可临时停用而不删除。
   - 顺手把 `updatedAt` 改成当天日期。
4. 提交 / 上传到 GitHub Pages。等部署完成后刷新页面即可看到新题。

> 提示：题库 JSON 必须是**合法 JSON**（双引号、逗号、无注释、无尾逗号）。提交前可用任意 JSON 校验器或 `node -e "require('./bank/setN.json')"` 验证。
